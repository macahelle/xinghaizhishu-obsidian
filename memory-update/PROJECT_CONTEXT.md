# 项目背景

## 项目目标

将个人资料组织成一个按“下次遇到什么任务时会使用”来导航的Obsidian知识库，而不是按文件来源堆放资料。

## 技术与文件形态

- Obsidian Markdown：正文、索引、规则和项目记忆。
- Obsidian Properties：使用YAML Frontmatter管理类型、领域、状态和更新时间。
- Obsidian Bases：`00-Wiki入口/02-知识库总览.base`提供动态表格视图。
- 工作台：`00-Wiki入口/00-星海工作台.md`使用原生任务、双链和 `03-工作台视图.base`，分别承载当前专注、进行中的项目、今日三件事和最近笔记。
- 主题与布局：`.obsidian/themes/星海知枢`负责深浅双模式；`.obsidian/workspace.json`采用左侧文件树、中央上方图谱、中央下方工作台、右侧关联信息的桌面布局；`.obsidian/graph.json`按一级目录分色。
- Obsidian Templates：模板目录为 `80-系统资源/模板`。
- 语音采集：核心录音机已开启；语音原件和转写统一进入 `90-资料收件箱/语音记录`，待在 Obsidian 中安装并配置本机转写插件。
- CSS片段：`.obsidian/snippets/tmac-wiki.css`。
- 无构建流程、后端服务和数据库；验证以文件解析、双链、属性和Obsidian界面为主。
- 当前目录不是Git仓库；除非后续初始化Git，否则不使用 `git status` 或 `git diff` 作为验证方式。

## 目录架构

| 目录 | 职责 |
|---|---|
| `00-Wiki入口` | 工作台、首页、使用说明和动态总览 |
| `10-主题知识` | 稳定知识、方法论和框架 |
| `20-工作流模板` | 可直接执行的提示词、SOP和清单 |
| `30-复盘沉淀` | 问题复盘、经验教训和质量标准 |
| `80-系统资源` | 模板、维护规则、台账和设计说明 |
| `80-系统资源/系统维护/项目记忆` | 项目背景、进度、决策和长期问题记录 |
| `90-资料收件箱` | 尚未判断归档方向的临时素材 |
| `Clippings` | 网页剪藏原文，保留来源，不视为正式知识 |

## 导航模型

`首页 → 父级索引 → 专题索引 → 正文`用于人工导航；Bases负责完整筛选。首页可以提供跨层快捷入口，但叶子正文原则上只在专题索引维护完整清单。

## Properties规范

- `type`：`hub`、`guide`、`index`、`knowledge`、`workflow`、`retrospective`、`rule`、`log`。
- `area`：所属业务主题或管理区域。
- `status`：`active`、`reference`、`draft`、`archive`。
- `updated`：最近一次实质整理日期。
- `tags`：用于主题聚合和图谱筛选。

## AI安全内容关系

- `AI安全威胁全景`提供全生命周期基础分类。
- `Agent安全风险框架`和`Skill能力供应链安全`负责专题风险分析。
- `智能体安全治理框架`负责企业治理设计和落地路线。
- `Agent安全审计清单`和`Skill安全管控清单`负责执行检查与证据记录。
- `Clippings处理台账`记录原始素材到正式笔记的沉淀关系。

## 日常使用与验证

1. 在Obsidian打开 `00-Wiki入口/00-星海工作台.md`，通过当前专注、项目、任务或最近笔记开始工作。
2. 需要系统浏览时，从工作台进入 `00-首页.md`、父级索引或专题地图。
3. 在知识库总览中检查类型、领域、状态和更新时间。
4. 新增正式笔记后检查对应索引、反向链接和Bases视图。
