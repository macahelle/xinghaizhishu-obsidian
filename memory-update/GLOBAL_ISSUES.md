# 全局问题与长期要求

## 用户长期要求

- 每次任务开始先读取项目规则、记忆索引和下一步任务，再按任务需要读取其他记忆文件。
- 优先最小修改，不做无必要的大范围重构。
- 修改后尽量执行YAML、双链、Properties、索引和视图验证。
- 每次完成后更新进度、下一步和必要的决策记录。
- 记录本次出现的错误模式和修改要求，避免同类问题重复发生。
- 面向公司高层的安全汇报应使用通俗业务语言，说明场景、影响和管理动作，避免技术术语堆砌。
- 高层综合安全汇报必须区分“需审批”和“需知悉”，审批事项前置；AI安全用实际工作流说明，设备参数和未经验证的效果数字放入附录或删除。
- 高层AI安全材料不直接出现具体AI产品名称，统一使用公众AI工具、编程辅助工具、内部智能体等类别名称；无法确认的数据在原位明确标注“待补充”。
- 必须区分“PPT编制规划”“逐页文案”和“实际PPT文件”；用户只要求规划时不得擅自生成PPT。
- 使用四步协作式PPT流程时，需求对齐、资料盘点、风格效果图、逐页成稿与文件生成必须逐阶段确认；最终交付必须是文字可编辑的 `.pptx`，不得用图片、PDF或网页替代。
- Clippings作者只作为普通文本保留；后续新增或整理剪藏时不建立作者双链、作者笔记或独立图谱节点，除非用户明确要求。
- 网络和AI安全方案中不得把“统一管理”直接设计为“所有业务流量串行通过一个中心节点”；规划必须同时说明容量、冗余、分流、扩容和故障切换机制。
- 介绍安全防护前应先说明业务、数据或算力的实际运行路径，再沿路径解释安全介入点，避免直接罗列安全设备和功能。
- AI场景分类必须采用同一维度；使用方式、建设方式、算力来源和模型来源不得在同一层级并列，确保每类场景都能唯一匹配管理流程和安全措施。
- 知识库根目录只保留必要的自动协作入口；后台记忆文件统一从 `80-系统资源/系统维护/项目记忆/` 导航，误生成的空笔记不留在根目录。
- 语音录音和未校对转写统一进入 `90-资料收件箱/语音记录`；公司与安全类内容默认本机转写，不自动删除原始录音。
- 手机快捷指令或其他外部工具新建 Markdown 时，必须在文件开头直接写入标准 YAML Properties；文件名日期使用 `yyyy-MM-dd-HHmmss`，不使用冒号、斜杠和本地化长日期。
- 星空工作台必须交付为可本地导入的完整主题包，包含主题外观、工作区预设和原生工作台数据层；不能用单篇HTML笔记冒充主题，也不能把需求缩减为只有星空背景。继续沿用现有 `00 / 10 / 20 / 30 / 80 / 90` 目录职责，不为视觉效果额外引入社区插件。
