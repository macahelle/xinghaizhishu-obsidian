# 重要决策

## D-001 按用途而不是来源组织正式知识

- 决策：稳定方法进入 `10-主题知识`，可执行内容进入 `20-工作流模板`，复盘进入 `30-复盘沉淀`。
- 原因：同一来源可能同时产生知识、清单和复盘，按用途更接近未来检索场景。

## D-002 保留分层索引，但限制重复职责

- 决策：首页负责快捷入口，父级索引负责区域边界和子主题，专题索引负责正文地图与阅读路径。
- 原因：完全取消索引会失去语义导航，每层重复罗列正文又会产生维护漂移。
- 约束：不再因为新建文件夹就机械创建索引。

## D-003 将AI安全知识与审计清单分区

- 决策：风险与治理框架放在 `10-主题知识/AI安全与智能体治理`；可执行清单放在 `20-工作流模板/AI安全审计`。
- 原因：前者回答“风险是什么、如何治理”，后者回答“具体检查什么、需要什么证据”。

## D-004 使用Properties和Bases管理完整性

- 决策：手工索引用于策展和阅读路径，Bases用于全部笔记和分类筛选。
- 原因：避免在多个手工页面重复维护完整清单。
- 约束：新增area时必须同步检查Bases筛选条件。

## D-005 项目记忆采用“根目录入口 + 系统维护归档”

- 决策：根目录只保留 `AGENTS.md`、`MEMORY_INDEX.md`、`NEXT_TASKS.md` 三个自动协作入口；`PROJECT_CONTEXT.md`、`PROGRESS.md`、`DECISIONS.md`、`GLOBAL_ISSUES.md` 放入 `80-系统资源/系统维护/项目记忆/`。
- 展示：三个根目录入口通过CSS仅在Obsidian文件树中隐藏，实际路径不变；人工统一从 [[项目记忆索引]] 进入。
- 原因：兼顾自动任务固定入口与知识库根目录整洁，不让后台协作文件混入日常笔记导航。
- 约束：移动记忆文件时必须同步更新 `AGENTS.md`、`MEMORY_INDEX.md` 和项目记忆索引中的路径。

## D-006 Clippings作者使用普通文本

- 决策：`Clippings` 的 `author` 属性只保存普通文本；默认不使用作者双链，不建立作者笔记或独立图谱节点。
- 原因：作者用于来源追溯，不属于当前知识库的主题知识关系；建立未解析作者双链会在全局图谱中产生无意义节点和连线。
- 例外：只有用户明确要求维护作者档案或作者关系时，才将对应作者升级为正式笔记。

## D-007 高层安全汇报按决策逻辑和AI使用方式组织

- 决策：面向集团总经理的正文控制为12页，网络架构改造和AI安全建设分别审批；网络安全和数据安全只说明现状运营与能力缺口。
- AI分类：采用外部AI工具直用型、内部AI助手交互型、业务系统嵌入型、AI自主执行型四类使用方式，逐类匹配管理措施。
- 管理边界：算力来源、模型来源、统一算力平台和安全API属于部署与安全接入模式，不作为独立AI使用场景。
- 架构原则：统一资产、规则和运营，防护能力分层部署、就近处理，避免网络出口或AI安全形成物理单点和访问瓶颈。

## D-008 语音记录先进收件箱并默认本机转写

- 决策：录音原件和未校对转写统一进入 `90-资料收件箱/语音记录`，校对提炼后再进入正式知识区域。
- 实现：默认使用支持本机 Whisper 的 Voice Scribe，将录音和新建转写笔记指向固定收件箱目录。
- 原因：Obsidian 核心录音机不转写，且其全局附件路径会影响所有附件；本机转写更适合公司和安全类敏感内容。
- 约束：不自动删除原始音频；使用云端转写前先确认数据处理要求，API Key 不写入笔记。
- 移动端规则：iPhone 快捷指令直接写入 `.md` 时，由快捷指令的“文本”动作生成完整 YAML；文件名日期使用 `yyyy-MM-dd-HHmmss`，不使用冒号和本地化长日期。

## D-009 星空视觉采用可本地导入的完整工作台主题包

- 决策：“星海知枢”的交付单位是“主题 + 工作区预设 + 原生工作台文件”，既不是单篇HTML页面，也不是只有星空背景的皮肤。
- 主题层：`.obsidian/themes/星海知枢/manifest.json`、`theme.css` 和星空资源负责深浅模式及全应用组件外观。
- 布局层：`.obsidian/workspace.json`负责左侧原有目录、中央“上方知识图谱 + 下方工作台”和右侧关联信息；`.obsidian/graph.json`按一级目录分色。
- 数据层：`00-星海工作台.md`使用原生Markdown任务和双链，`03-工作台视图.base`提供动态最近笔记；CSS关闭后任务、链接和数据仍可使用。
- 原因：Obsidian主题CSS不能创建视图或业务数据，完整工作台必须由三层协作；这样既能全局统一视觉，也保留真实任务、反向链接、图谱和重命名同步。
- 约束：保持 `00 / 10 / 20 / 30 / 80 / 90` 目录职责；不使用HTML或CSS伪造任务、项目、日历和进度，不为视觉效果额外引入社区插件。
